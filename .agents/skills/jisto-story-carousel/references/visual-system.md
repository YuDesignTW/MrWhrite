# 圖像敘事版型

製作前至少實際查看一篇相近範例：[OXO](selected-oxo-overview.jpg)、[IKEA](selected-ikea-overview.jpg)、[Mailchimp](selected-mailchimp-overview.jpg)。這些是基準縮圖，不是可直接挪到新題材的背景素材。

最新偏好：V4 文案搭配 V3 排版。上述縮圖是 V5 組合輸出，頁數與故事順序依 V4；圖片版型依 V3 回套，長正文可調整間距。選擇版型時須符合當頁內容，不恢復舊版刪除的旁支。

## 畫面基準

| 項目 | V3 版型的實作基準 |
|---|---|
| 輸出 | 1080×1350，4:5 |
| 字體 | Noto Sans TC；專案內名稱 Jisto Poster |
| 左右主要留白 | 約 76px，可用寬度約 928px |
| 大標 | 約 73–88px、粗體；依句意斷行 |
| 正文 | 約 40–44px、行高約 1.46–1.5 |
| 眉標 | 約 25–30px，短而有用 |
| 小字 | 約 19–22px，限來源、圖說、頁碼；不拿來塞主內容 |
| 顏色 | 墨黑 #171713、暖白 #fffaf1、紙色 #f2eee5、少量橘色 #ffb04b |
| 識別 | 小型 JISTO／品牌故事與頁碼，細線；不搶主圖 |

這是可延續的起點，不是每張必須完全相同的座標。排版應照顧新照片主體與正文長度；中文可讀性優先於英文字數公式。

## 可混用的六種配置

1. **滿版照片＋文字**：圖片鋪滿，短大標與段落放在不遮住重點的位置。黑色半透明層加局部漸層，讓照片有內容、文字也能讀。第二稿一般照片使用約 20–30% 全圖黑層，文字側再加深，不照抄透明度而忽略新圖亮度。
2. **照片＋淺底說明**：上方大圖，下方紙色內容區，適合型錄、原型、肖像與需要完整展示的照片。第二稿分界約 y=670，圖說接在圖片下方。這種明暗交替也屬於認可方向。
3. **產品細節標註**：照片是主角，短標籤與引線指出真實可見的部位。線不能指錯；不可讓原型照片變成「量產規格」的虛構證據。
4. **人物並列**：官方肖像配姓名，幫讀者建立人物關係。不要虛構兩人同場的合照。
5. **資料並列**：如型錄強調低價、製造紀錄卻指出成本高。少量文字搭相關圖片，不把一切都變成資訊表或假數據圖。
6. **時間線**：用確認過的年份與事件串起時間，背景仍與故事相關。大數字要標明性質，不能把交易價當成營收。

由故事選配置，不要求每篇把六種都用完。相同圖片可以換景別或回到開頭形成呼應；若連續多頁的構圖、文字位置與資訊都雷同，重新安排。

## 看圖時特別檢查

- 主體看得出來嗎？滿版裁切是否切掉要介紹的產品或人物？不必為鋪滿而破壞證據。
- 正文在手機大小能否輕鬆閱讀？黑層是否太淺，或深到圖片只剩裝飾？
- 中英文、標點和金額斷行是否自然？英文單字結尾加標點不可被拆成孤立字母。
- 標題、正文、圖說、來源有沒有互相擠壓？適量留白不等於要再塞一段道理。
- 圖片跨頁的使用是否有意義？每頁仍應有新資訊，不能只換背景來延長篇幅。
- 情境插圖在出現的每頁保留示意標記；不靠讀者去查附件才知道圖是生成的。

## 可重用的專案實作

目前組合 `output/ig-story-v5-2026-11-08/`（V3 版型來源保留在 `output/ig-story-v3-2026-11-07/`）：

- `posts.json`：逐頁文字、來源、圖片、版型、crop 與時間線事件。
- `editorial.mjs`：上述版型的原生 Canvas 渲染。
- `render.mjs`：生成 PNG、縮圖、alt text、文案與 HTML。
- `package.py`：PNG 尺寸、檔案連結、ZIP CRC 與打包檢查。

這些是該三篇的實作範例，不是通用 App 功能。重用時另建輸出目錄，檢查人物並列中的圖片 key、產品引線座標、圖片信用行與文件連結等案例專用值。不要直接對原資料夾重跑產生器覆寫認可版本。

不要依賴開發時的暫存 Canvas 套件路徑；先確認目前環境與專案字型。若只製作內容，無需安裝渲染環境。
