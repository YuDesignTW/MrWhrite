# 發文文案與 hashtag

使用者在認可三篇輪播後補充：圖中文字要連貫，看完是一個完整故事；也要處理發文的文案，包含 hashtag。這是後續製作要求，並不代表已認可每一份新文案。

## 與輪播分工

輪播自己把故事講完。Caption 給讀者另一個值得讀的角度：作者在意的一個細節、這件事和讀者工作／生活的關係，或輪播沒展開的背景。它可以簡短交代故事，但不要逐頁複製，也不能靠 caption 才把輪播中的斷裂補好。

2026-11-08 使用者指出第三稿仍不順、AI 口吻強。Caption 也須讓第一次看到它的人讀懂主角與事件；可以重述理解觀點所必需的故事背景，不為避免重複而直接從抽象問題、寫作心得或泛用教訓開始。開頭優先放這一篇獨有的具體事件。

先決定本篇 caption 想多說哪一件事。不要同時寫摘要、觀點、教學、宣傳與多個行動邀請。

## 可直接貼上的內容

- 用一句具體、完整的開場；不必再使用輪播封面的同一句話。手機收合前能理解意思即可，不把固定字數當作跨版本不變的顯示保證。
- 以短段落自然延伸一個觀點。避免空泛升華、假個人經驗，以及「這個品牌教會我們」式課堂口吻。
- 需要互動才放一個跟故事有關的問題；有自然結尾就可以停，不強制留言／收藏／追蹤。
- 末尾可加簡短來源名稱；完整網址與圖片出處放獨立的來源留言檔，不宣稱已經貼出留言。圖片若是情境示意，保留必要說明。
- Hashtag 放在最後獨立一行。先以少量具體標籤起稿，例如 3–5 個：品牌／產品名稱、主題、讀者關注的領域，再視需要加 #JISTO。這是編輯預設，不是平台規則或觸及保證；使用者另有偏好就調整。
- 只選真正對應內容的標籤。不為湊數使用 #viral、#fyp 等，也不未經研究就聲稱某標籤熱門或保證曝光。要回答平台限制或熱門程度時，另查最新官方資料。

## 檔案分工與檢查

- `caption.txt`：只有準備貼到 IG 的正文、必要短註與 hashtag；不含「以下為文案」或編輯評語。
- `first-comment.txt`：完整文字來源、圖片信用與必要補充，供使用者自行發出。
- `copy.md`／來源對照：逐頁稿、事實／推論與查核備註，保留為工作紀錄。

連續讀完輪播後再讀 caption：有沒有重複太多？觀點是否來自這個故事？hashtag 是否真的相關？全文是否方便直接複製？確認日期、金額及人名跟圖片一致。

若使用專案 ig-caption／ig-human 腳本，只把它們當機械檢查；固定收合字數、英文 CTA 偵測與中文自然度等判斷需要人工覆核。不為消除不適用的警告加入多餘的行動邀請。
