# 多 Agent 創作工作台

更新：2026-11-05。

## 最新介面：五個入口，功能放進對話

左側改為「創意總監、策略、創作、編輯、互動」，分別使用星芒、羅盤、畫筆、編輯筆及對話圖示。下方的舊版 Agent 對照表現在代表內部功能，而不是 14 個聊天室入口。

- 策略：對標研究、內容企劃、品牌定位、成效分析。
- 創作：輪播、貼文文案、短影音、限動、內容再製。
- 編輯：語氣修整。
- 互動：留言、留言回覆、合作私訊。
- 創意總監：統整需求並調度專長工作。

在輸入框上方選功能，或保留「自動選擇」直接描述需求。同分類內切換功能不換聊天室、不清空輸入；自動模式提供該分類的方法，指定模式只載入選定 skill。總監交辦的專長紀錄也會歸入對應分類。

## 資料實際存在哪裡

預設資料庫是 `mr-white/data/database.sqlite`，若設定 `MR_WHITE_DATA_DIR` 則跟隨該路徑。SQLite 的 `records` 表以 `kind`、`id`、JSON `data` 儲存記錄：

| 內容 | 儲存方式 | 共用範圍 |
| --- | --- | --- |
| 已送出對話 | `agentMessage`，含角色、文字、agentId 與任務關聯 | 按分類顯示；舊 specialist ID 保留 |
| 任務與派工成果 | `agentRun`，含狀態、skillId／技能版本、步驟及結果 | 總監與相關分類可查看 |
| 待審草稿 | `agentDraft` | 共用審核佇列，包含版本保護 |
| 寫作偏好 | `agentPreference` | 所有分類共用，可停用、修改 |
| 正式作品與文章 | `work`、`article` | 沿用既有作品庫 |
| 未送出的文字、選定功能與目前分類 | 瀏覽器 localStorage | 每個瀏覽器獨立；未送文字依分類區分 |
| Skill 方法 | `.agents/skills/ig-*/SKILL.md` | 專案檔案，服務啟動時載入 |

策略／創作／編輯／互動是同一資料庫上的邏輯分類，不是各自一個資料夾或資料庫。舊記錄透過固定對照表呈現，不做破壞性遷移。舊 skill 聊天室的未送文字會一次性帶入所屬分類，原 localStorage key 仍保留。

Agent 使用同一個本機模型執行器，以角色、技能與上下文區別，沒有個別模型訓練或永久自動學習。儲存的完整歷史不代表每次全部送給模型：目前畫面讀取最近 120 則該分類訊息，一般生成帶入最近 10 則，再加本次來源、追問任務、選定稿件與有效偏好。技能切換不是清除上下文。

既有 SQLite 快照備份會包含上述已送對話與任務；瀏覽器 localStorage 的未送文字不在資料庫備份內。Chrome 訪客工作階段結束後，不應依賴其中的未送文字仍存在。

分類 API 使用 `GET /api/agent/state?agentId=creation`；送出可指定 `agentId: "creation", skillId: "ig-carousel"`。省略 skillId 為自動模式。舊 specialist API 仍可使用，保留既有資料相容性。

## 使用方式

1. 進入「創作工作台」，左側選擇分類。窄螢幕改為上方可橫向捲動的選擇列。
2. 直接描述任務，或按「試試這個任務」帶入範例後補充素材。每位 Agent 有獨立對話與未送出文字。
3. 複合任務交給「創意總監」，例如：「請讓對標研究員分析我提供的案例，再讓輪播設計師提出六頁內容，最後由語氣編輯潤飾。」
4. 「團隊任務」顯示各步等待、執行、完成或中斷狀態。點 Agent 名稱可進入該專長對話；展開「查看成果」可讀取已完成結果。
5. 專長 Agent 能直接續聊；完整稿包仍在右側共用待審佇列，核准後才保存作品。核准不等於發布。

首次生成沿用既有 AI 資料告知。一次總監調度最多三位不同專長，採依序執行，再呼叫總監彙整，因此比單次聊天使用更多模型呼叫與時間。所有工作共用本機單一執行鎖，任務中可以切換閱讀，待完成或停止後再送新任務。

## Agent 與技能

| Agent | Skill | 工作 |
| --- | --- | --- |
| 創意總監 | 協調協定 | 分工、派工、整合成果 |
| 對標研究員 | ig-viral | 根據提供的案例分析開場、結構與高流量證據 |
| 內容企劃 | ig-plan | 選題與內容計畫 |
| 品牌定位顧問 | ig-profile | 帳號自介、追蹤理由與品牌表達 |
| 輪播設計師 | ig-carousel | 封面、逐頁內容與畫面方向 |
| 貼文文案 | ig-caption | IG 文案與行動邀請 |
| 短影音編導 | ig-reel | 口播、畫面文字與分鏡 |
| 限動企劃 | ig-story | 限動故事與互動 |
| 內容再製 | ig-repurpose | 長文／逐字稿轉為多種內容 |
| 語氣編輯 | ig-human | 自然語氣與制式文案修整 |
| 成效分析師 | ig-audit | 根據實際數據檢討內容 |
| 互動文案 | ig-comment | 草擬別人貼文下的留言 |
| 留言回覆 | ig-reply | 草擬自己貼文下的回覆 |
| 私訊顧問 | ig-dm | 草擬合作邀約與私訊 |

本次功能是對話、專長方法與實際模型調度。技能檔案中的工具指令不會自動獲得執行權限：尚未新增即時搜尋、腳本執行、圖片生成、影片渲染或私訊傳送。沒有來源與數據時應請使用者補充，不得冒充已研究或已驗證高流量。英文評分腳本亦未當成中文品質分數。

## 資料與執行契約

- `server/agent-catalog.mjs` 固定列出允許的 Agent 與技能路徑，啟動時讀取對應 SKILL.md 並計算版本。修改 skill 後重啟服務才會載入新內容。
- `GET /api/agent/state?agentId=ig-carousel` 回傳該 Agent 的訊息與直接任務、交辦任務，以及共用草稿、來源、偏好與全域執行狀態。未指定時為 `coordinator`。
- `POST /api/agent/messages` 支援 `agentId`。訊息識別碼的冪等驗證包含 Agent；追問只能在同一 Agent 中接續。既有未標記記錄預設歸總監，無須破壞性資料遷移。
- 總監輸出受驗證的 `delegations`，伺服器依序執行，各專長收到原需求、指定素材與先前步驟的成果；不同 Agent 的私人對話背景不會自動混入。專長與彙整階段禁止遞迴調度。
- 步驟保存任務、技能版本、狀態與已完成成果；專長對話亦保留交辦與答覆。正式稿包由最後總結建立待審候選；專長中間稿包保留在步驟成果中。
- 草稿、資料 epoch、作品／文章版本、審核與既有備份保護沿用原有機制。對話中的來源與模型結果仍視為資料，不能覆寫系統邊界。
- 取消會取消目前模型呼叫並停止後續步驟；遲到結果不寫入。失敗保留已完成成果；重啟將執行中工作標為中斷，不自動重送。

驗證狀態以 [CURRENT-STATUS.md](CURRENT-STATUS.md) 為準。可控模型測試不等於真實模型或外部平台驗收。
