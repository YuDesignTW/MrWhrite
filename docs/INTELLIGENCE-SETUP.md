# 情報室 v0.2 設定與執行邊界

目前為實作中版本。資料層與 HTTP 自動測試通過不代表 Meta／IG 真實整合或畫面驗收完成。完整紀錄見 [工程迴圈紀錄](LOOP-LOG.md)。

## 不需任何外部帳號的功能

寫作空間上方切到「情報室」→ 新增情報 → 貼上文字 → 保存。可搜尋、按平台／來源／臺北發布日期篩選、收藏、移至垃圾桶與恢復、建立獨立文章草稿。

可先保存待驗證的帳號來源；缺憑證時不啟用排程、不宣稱抓取成功。排程時區與每天時段可先保存。沒有平台設定時，Threads 發布按鈕不能完成發布。

## 本機設定

使用 Node 22.22.0。啟動器會讀取專案根目錄的 `.env`（已被 gitignore 排除）；`.env.example` 只有空白欄位，沒有真實密鑰。

| 變數 | 用途 |
| --- | --- |
| MR_WHITE_THREADS_APP_ID | 自己的 Meta Threads App ID |
| MR_WHITE_THREADS_APP_SECRET | 自己的 App Secret，僅後端使用 |
| MR_WHITE_THREADS_REDIRECT_URI | 官方應用已註冊的完整回呼網址；實際允許的 HTTP／HTTPS 規則須在 Meta 驗證 |
| MR_WHITE_CREDENTIAL_KEY | 32 隨機 bytes 的 64 位十六進位加密金鑰，不是密碼；妥善保管 |
| MR_WHITE_THREADS_READ_TOKEN | 可選的讀取權杖，僅供讀取，不取代官方發布綁定 |
| MR_WHITE_APIFY_TOKEN | 選用的付費 IG 資料供應商憑證；啟用前先確認覆蓋與服務預算 |

不要把密鑰貼到文章、情報或聊天。沒有建立 Meta 應用時可保留所有欄位為空，仍可使用手動情報與文章功能。

啟動沿用 README 的 `npm run dev`，服務只監聽 127.0.0.1。相同資料目錄有程序鎖，不能同時啟動兩個伺服器處理工作。此版本不是雲端多人服務，不可直接把 Codex 本機後端公開。

## Threads 官方授權與發文

1. Meta 應用配置完成後，到情報室 → Threads 發布 → 前往官方授權。
2. 目前採本機人工完成回呼：官方授權後將完整回呼網址貼入「完成官方回呼」，須在同一瀏覽器工作階段十分鐘內操作。這是一次性 OAuth code／state，不是帳號密碼。
3. 後端交換長期權杖並查詢帳號識別；只有確認帳號成功才保存綁定。
4. 已取得未過期、滿一天的權杖可按「更新授權期限」；過期則重新授權。本版尚未做自動定時續期。
5. 編輯器「發布 Threads」會先保存文章、轉純文字並顯示帳號及內容。使用者確認後才建立發布工作。
6. 當前保守限制為 500 Unicode code points；需在官方整合驗收時核對平台實際計數及限制。超長不截斷、不自動拆串。

權杖以 AES-256-GCM 加密，儲存在資料目錄的 credentials 子目錄，檔案 mode 0600；加密金鑰不寫入資料庫。一般 SQLite／Drive 備份不包含權杖或加密金鑰。解除綁定取消尚未執行的發布，保留發布歷史。

原先的 Host／Origin 保護只接受本機來源。若官方回呼需要 HTTPS／遠端網域，必須另行設計安全回呼方式；本版未放寬本機 Host 限制，也未部署公開回呼。

## Threads／IG 讀取 adapter

- Threads：官方 profile lookup／profile posts。需真實驗證讀取第三方帳號的權限。單篇 URL 現階段在該公開帳號最多 100 篇可讀貼文中比對，不能保證任意年代貼文可讀。
- IG：已寫選用的 Apify instagram-scraper adapter，尚未購買、配置或真實驗證。它不是官方發文路線；所有發布仍只用 Threads 官方 API。
- 官方讀取遇到暫時性錯誤最多嘗試三次；不重試發文副作用，也不自動重跑可能計費的 Apify 工作。較長限流等待留待下一時段／手動重試。
- 帳號搜集上限 100 篇；到上限、分頁中斷或缺可信日期標示「部分完成」，不宣稱完整當日歸檔。
- 今日由設定時區決定，排除回覆與非當日貼文。最後一次更新後才發的跨日貼文不回補。
- 已記錄媒體中繼資料；目前 UI 提供原文入口，尚未提供圖片縮圖牆或下載影片。
- 不使用非官方平台登入，不嘗試登入牆繞過，不以提供者不可讀時的空陣列假裝通過帳號驗證。

## 排程與資料保護

- 搜集、發布分開計時；單一來源讀取緩慢不阻塞發布時計。
- 本機服務需保持運行。搜集補做最新當日時段；發布重啟逾期不補發，延誤超過兩分鐘標示 missed。
- 發布先保存文字快照與容器 ID，遠端結果不明保持 unknown。可查容器狀態，但沒有遠端貼文 ID 時不自動改成 published 或重送。
- 改期只支援 queued／missed；unknown 必須先人工核對平台，現階段不提供一鍵重送。
- 還原時凍結未發工作，publishing／unknown 保持 unknown；不讓舊備份重複發文。
- 同資料目錄只允許一個 CLI 服務程序，不宣稱支援分散式多 worker。

## 驗收工具

- `npm test`：既有及新增的資料／HTTP／錯誤邊界測試，真實服務使用替身。
- `npm run build`：正式前端與既有 Sites 打包。
- `npm run test:sites`：保留的 Sites 打包契約。
- `scripts/verify-social-browser.mjs`：選用 Chromium 操作檢查，需設定 MR_WHITE_CHROME 執行檔路徑；以 pipe 與記憶體 HTTP 接上真實 Express，使用獨立暫存資料、不開監聽埠。2026-11-04 本環境 Chromium 仍被作業系統阻擋，沒有通過結果。

正式外部驗收仍需真實帳號、權限、資料提供者與指定測試發文內容；目前沒有公開發布任何文章。
