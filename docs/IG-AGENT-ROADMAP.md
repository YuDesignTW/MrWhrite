# 懷特先生：本機 Codex IG 製作流程

決策日期：2026-11-07。使用者選擇繼續完善懷特先生，以經營自己的 IG 為核心。

## 方向

保留本機 App、SQLite、作品版本與 Codex CLI。流程和素材在 Mac，模型呼叫沿用既有登入；不宣稱離線推論、無限用量或電腦休眠仍可工作。先完成可追查的內容流程，再依實際工具需求評估 Docker Worker。不重寫成通用助理平台。

## 第一階段：執行環境與內容審查

目前新增 `server/ig-workflow.mjs`，由程式控制順序：

1. 輪播與文案創作：載入 ig-carousel、ig-caption 方法。
2. 獨立內容審查：另一次 Codex 呼叫，載入 ig-human 方法，逐案檢查事實依據、開場價值、逐頁敘事、語氣、caption。
3. 不通過時退修一次，再獨立複查。最多四次模型呼叫；簡單聊天或追問只有一次。
4. 審查通過才交付提案卡片；未通過的候選仍保留在製作紀錄。文字審查通過不等於用戶喜歡，也不等於已驗收圖片。

每一步保存狀態、技能版本和結果；任務保存來源與偏好快照。重啟不自動重送，取消不執行後續步驟，舊提案不被覆蓋。介面可展開讀取初稿、退修稿、具體審查依據。角色共用模型，不代表不同模型訓練或獨立模型觀點。

使用既有 Codex 沙箱及工具限制。Skill 本階段只作方法指引，沒有啟用英文偵測腳本、任意 shell、搜尋、原生多 Agent 或圖片生成。審查每案必須具備五個檢查及具體依據，缺項或格式失敗就回報失敗，不降級成假成功。

驗收入口：`npm test`、`npm run build`、`npm run verify:codex`、`node scripts/verify-ig-workflow.mjs`。最後兩個會使用真實 Codex 額度，使用暫存目錄；輪播驗收走實際 API 與隔離 SQLite，不寫入正式作品或發布內容。

## 第二階段：研究、製圖與視覺審查

- 研究：把既有素材擷取與可核對的外部來源接成受控任務，保留來源、時間、引用與不可取得的資料。沒有素材時不假造研究。
- 設計：明確定義視覺簡報與素材需求，提升現有固定模板的編排能力。以使用者選定的實際案例建立參考，不只增加配色。
- 成品審圖：生成實際 PNG 後交給多模態審查，檢查手機可讀性、溢出、視覺層級、素材與文意一致性；結合確定性尺寸／溢出檢查。
- 工具隔離：依素材下載、字型、渲染工具的需求評估 Worker 容器，限制掛載、網路與憑證；不把整個個人設定目錄交給工作容器。

驗收：一個來源到一份完整輪播，含實際素材、圖片、審圖回饋與修改成果；程式測試與真實視覺驗收分開記錄。Chrome 必須使用可確認的新 Guest 視窗；桌面控制另需明確同意。

## 第三階段：品牌品質與營運

保留目前不滿意的作品作比較基準。以三個固定題目做新舊對比，由使用者判斷是否願意發布、是否符合品牌、修改負擔是否下降。將具體喜好與負面範例納入可編輯的品牌指引；不以自評分數或虛構流量取代品質。

後續再處理經用戶確認的發布流程與實際成效回填。建立作品不等於授權公開發文。
